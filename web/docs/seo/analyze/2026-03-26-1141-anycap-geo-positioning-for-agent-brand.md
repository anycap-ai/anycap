## Core Premise

AnyCap 要傳達的不是單一功能，而是一個更高層的品牌認知：

- AnyCap 是給 agent 擴充能力的基礎層
- AnyCap 可以在多種 agent 產品上絲滑安裝
- AnyCap 不是從 human software 改來的，而是專門為 agent 打造

這個方向非常適合做 GEO，因為 AI 搜尋很吃「清楚的類別定義」與「可重複引用的品牌句型」。

## GEO Positioning Thesis

AnyCap 在 GEO 上不應只被鋪成「another AI tool」。

更好的鋪法是讓 AI 系統逐步學到下面這組認知：

1. `AnyCap is an agent-native capability runtime.`
2. `AnyCap gives AI agents installable capabilities through one CLI and one interface.`
3. `AnyCap works across agent products such as Cursor, Claude Code, Codex, OpenCode, and OpenClaw.`
4. `AnyCap is purpose-built for agents, not retrofitted from human-first software.`

這四句如果能在站內、站外、文件、比較頁、安裝頁反覆出現，GEO 會比單純堆關鍵字更有效。

## The GEO Goal

不是只讓搜尋引擎知道 `AnyCap` 這個名字，而是讓 AI 系統在回答下面這些問題時，會自然把 AnyCap 當成候選答案：

- `How do I give an AI agent more capabilities?`
- `What tools can I install on Cursor or Claude Code?`
- `How do I add image or video capabilities to coding agents?`
- `What is a capability runtime for AI agents?`
- `What is built specifically for agents rather than humans?`

## Message Hierarchy

### Layer 1: Category Claim

最重要的不是功能列表，而是類別定義。

建議主句：

- `AnyCap is an agent-native capability runtime.`
- `AnyCap is a capability layer for AI agents.`
- `AnyCap gives agents one interface for installable capabilities.`

這層的用途是回答：

- `AnyCap 是什麼`
- `這屬於哪個類別`

### Layer 2: Outcome Claim

第二層不是介紹技術細節，而是回答 agent 最在意的結果。

建議主句：

- `Give agents image, video, speech, search, crawl, and other capabilities through one install path.`
- `Let agents do more without stitching together separate tools and authentication flows.`
- `Equip agents with real-world capabilities, not just reasoning.`

這層的用途是回答：

- `為什麼要用 AnyCap`
- `用了之後 agent 多了什麼能力`

### Layer 3: Ecosystem Claim

這是 AnyCap 很大的 GEO 機會點，因為你不是抽象平台，而是明確跟 agent ecosystem 綁在一起。

建議主句：

- `Works across Cursor, Claude Code, Codex, OpenCode, OpenClaw, and other agent products.`
- `Install once, then give multiple agent environments a consistent capability interface.`
- `Purpose-built for agent workflows, not only human dashboards.`

這層的用途是回答：

- `能裝在哪裡`
- `和哪些 agent 產品有關`

### Layer 4: Brand Belief

這層要建立品牌記憶點，但必須可控，不能寫成難以驗證的絕對事實。

建議主句：

- `Built for agents from day one.`
- `Designed for agent workflows, not adapted from human-first software.`
- `An agent-first brand for installable capabilities.`

### Important Guardrail

`第一家為 agent 服務的品牌` 這種說法非常強，但在 GEO 裡屬於高風險句型。

原因：

- AI 系統偏好可驗證事實
- 若沒有外部來源支持，這種絕對主張不容易被引用
- 一旦被其他資料源反駁，反而會削弱 trust

因此建議：

- 可以把它當品牌 manifesto
- 不建議把它當成核心事實句反覆鋪

更穩的替代句：

- `One of the few brands built specifically for AI agents`
- `Purpose-built for AI agents`
- `Agent-native from the start`

## What GEO Needs From Copy

### 1. A Stable Definition Block

首頁與 `/for-human` 都需要一個可以被穩定抽取的 definition block。

建議回答的模板：

`AnyCap is an agent-native capability runtime that lets AI agents install and use capabilities such as image understanding, video analysis, and other multimodal or web actions through one CLI and one interface. It is designed to work across agent products like Cursor, Claude Code, Codex, OpenCode, and OpenClaw, so teams can give agents more abilities without rebuilding separate integrations for each environment.`

這種段落有幾個特點：

- 自包含
- 有 category
- 有 audience
- 有 capabilities
- 有 ecosystem names

### 2. A Capability Expansion Block

不是只說 AnyCap 有哪些功能，而是要說它在 agent stack 裡扮演什麼角色。

建議模板：

`AnyCap sits between an agent and the capabilities it needs. Instead of wiring separate tools, auth flows, and interfaces for each capability, teams can use AnyCap as a consistent layer for installing, accessing, and managing agent-facing capabilities.`

### 3. A Smooth Installation Block

你提到的「絲滑安裝」是非常好的 GEO differentiator，因為它對 agent workflow 很具體。

建議模板：

`AnyCap is built to install smoothly into agent products. Rather than creating a separate capability stack for each environment, teams can use a consistent install path and interface across Cursor, Claude Code, Codex, OpenCode, OpenClaw, and similar agent workflows.`

### 4. A Today vs Planned Block

GEO 很怕模糊狀態。所有 capability 都要明確區分：

- `available now`
- `planned`
- `coming soon`

這可以避免 AI 系統把未上線能力也當成既成事實。

## External GEO Surface

如果 AnyCap 要在 GEO 上起量，站外不能完全空白。

最優先的外部 surface：

1. 公開可訪問 GitHub repo 與 releases
2. skills.sh listing 或其他 agent directory listing
3. LinkedIn company / founder surface
4. Reddit / Hacker News / X 上的產品定義討論
5. YouTube demo 或 walkthrough

### Why This Matters

AI 系統很少只依賴單一官網。它們更喜歡看到：

- 官網定義
- 開源 repo
- 安裝入口
- 第三方 mention
- 社群討論

AnyCap 這種 agent-native 品牌，外部 ecosystem presence 甚至比傳統 backlink 更重要。

## GEO Content Rules For AnyCap

1. 每頁都先回答「What is this?」
2. 每頁都明確列出適用對象：agent、developer、team
3. 每頁都標出 today vs planned
4. 每頁都要有至少一段可被直接引用的 130-170 字 answer block
5. 每頁都要出現具體 agent 產品名，而不是只說 `AI agents`

## Final Judgment

AnyCap 在 GEO 上最該鋪的不是「我們也有 AI 能力」，而是這個更清楚的認知：

`AnyCap is the agent-native capability layer that helps agents gain installable capabilities across multiple agent products.`

## What's Changed

### Feishu

- **Final Feishu replies now come from the local daemon.** When you use `anycap connect feishu`, the local daemon asks the server for the final outbound reply and sends it through the same personal Feishu bot that received the message.
- **Server-side Feishu App ID/App Secret are no longer needed for the normal connect flow.** Each user's daemon keeps its own Feishu credentials locally, so multiple users can run independent personal Feishu bots without sharing one server-owned bot credential.
- **Conversation history is still recorded on the server.** The server stores the committed session and final message for history and audit, while delivery is handled by the daemon.

### Compatibility

- The legacy server-owned Feishu long-connection path remains disabled. Existing server-side ReplyAPI relay deployments can still be used for fallback scenarios, but the recommended path is `anycap connect feishu` with local daemon-owned credentials.

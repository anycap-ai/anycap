## What's New

### Connect chat apps to local coding agents (`anycap connect`)

`anycap connect` is a new top-level command that wires a chat app (currently Feishu) directly to a local coding agent (Codex, Claude Code, or Cursor Agent). The connection runs as a local background daemon: the chat app's long connection terminates on your machine, and replies are produced by the coding agent running in your workspace.

```bash
# Connect Feishu to Codex in the current repo
anycap connect feishu --agent codex --workspace /path/to/repo

# Use Claude Code instead
anycap connect feishu --agent claude_code --workspace /path/to/repo

# Use Cursor Agent (auto-enables --force for non-interactive runs)
anycap connect feishu --agent cursor --workspace /path/to/repo

# Inspect or stop the local connection
anycap connect status feishu
anycap connect stop feishu
```

Credentials for the chat app are stored locally so the daemon survives terminal restarts:

```bash
anycap connect credentials set feishu \
  --app-id <FEISHU_APP_ID> \
  --app-secret <FEISHU_APP_SECRET>
anycap connect credentials show feishu
```

The lower-level `anycap agent daemon ...` commands remain available for debugging and scripting.

### New executors for the local agent daemon

The local daemon (`anycap agent daemon` and the new `connect` flow) can now drive three coding agents:

- **Codex** -- default. `--codex-exec-mode safe` (maps to Codex `--full-auto`) is the default; pass `--codex-exec-mode danger-full-access` when you want the chat-driven Codex turn to call AnyCap commands or reach public/internal network resources.
- **Claude Code** -- `--agent claude_code` runs `claude -p --output-format json` and persists the Claude Code `session_id` for follow-up turns. Use `--claude-permission-mode bypassPermissions --claude-allowed-tools Read,Edit,Bash` when the chat-driven Claude Code turn needs network or shell access.
- **Cursor Agent** -- `--agent cursor` runs `cursor-agent -p --output-format json --trust --force` on the user-facing connect path and persists the Cursor `session_id` for follow-up turns. Use `--cursor-model <model>` for explicit model selection.

### Feishu personal-bot daemon improvements

The personal Feishu daemon that ships with `anycap connect feishu` is significantly more robust:

- Long-connection ingress for low-latency message delivery
- Non-text messages (images, files, docs) are ingested and made available to the coding agent
- Feishu-shared documents and resource URLs are read on demand and written back as docx, sheet, and bitable actions
- Inbound context is enriched before the agent turn (recent messages, attachments, replied-to content)
- Burst messages from the same user are merged into a single agent turn, with deduped acknowledgements
- Replayed Feishu events are deduplicated so retries no longer trigger duplicate agent runs
- Markdown replies from the agent are rendered as Feishu rich text
- Feishu credentials can be loaded from `FEISHU_APP_ID` / `FEISHU_APP_SECRET` env vars in addition to the local credentials file

## What's Changed

### New: Snapshot

Portable project handoff via a single AnyCap Drive share URL. Use Snapshot when another agent, machine, or account needs a recoverable working set -- not just a single file download.

- `anycap snapshot create` packages one or more local targets into a tar archive, uploads it to Drive under `/_snapshots/{name}.snapshot.tar`, creates a password-protected expiring share URL, and returns a ready-to-run restore command.
- `anycap snapshot restore <share-url>` parses the inline `#password=...`, downloads the archive via the raw share route, and restores it into the target directory with safety checks against absolute paths, `..` traversal, and non-regular entries.
- Repeatable `--target` for multi-target bundles, `--overwrite` to replace an existing same-name snapshot, `--force` to bypass sensitive-file guards, and `--expires` to control share lifetime.
- Common technical directories (`node_modules`, `.git`, `.venv`, `dist`, `build`, caches) are skipped automatically.

### Examples

```bash
anycap snapshot create --target . --target README.md --name repo --expires 7d
anycap snapshot restore 'https://drive.anycap.cloud/s/abc#password=secret' --target ./restored
```
